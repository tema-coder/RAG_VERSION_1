# constraints.txt — зафиксированное рабочее окружение rag_parser.
#
# Формат установки (см. README, раздел «Установка»):
#     pip install -r rag_parser/requirements.txt -c constraints.txt
#
# requirements.txt хранит ТОЛЬКО верхнеуровневые зависимости сервиса с
# мягкими диапазонами версий; этот файл фиксирует полный транзитивный
# набор, который реально работает вместе с dedoc 2.8. Причина: у dedoc
# жёсткие пины (например scipy<=1.11.2, python-docx==0.8.11,
# starlette<=0.27.0), которые тянут за собой конфликты с FastAPI/Streamlit.
# Фиксируем рабочее состояние, а не гонимся за идеальным pin'ом.
#
# Сгенерировано: python -m pip freeze (Python 3.12.14).
# torch указан без локального тега "+cpu": сборка выбирается индексом
# (см. README, шаг 1 установки), pip не может разрешить "+cpu" с PyPI.
#
# torch — транзитивная зависимость (dedoc, sentence-transformers) и в
# requirements.txt не указан: прямой пин ломает резолвер.
#
# ЧТО НАМЕРЕННО НЕ ЗАКРЕПЛЕНО (17 пакетов) и почему
# ----------------------------------------------------
# pip freeze зафиксировал версии, которые ВЫХОДЯТ за жёсткие спеки dedoc 2.8
# (dedoc — пакет 2023 года). Держать такие пины нельзя: чистая установка
# падает с ResolutionImpossible. Их версии резолвит сам pip по спекам dedoc:
#
#   beautifulsoup4, charset-normalizer, pdfminer.six, puremagic, pypdf,
#   pytesseract, roman, scipy, starlette, ujson, uvicorn, xgboost,
#   scikit-learn, huggingface-hub, python-docx, python-multipart,
#   scikit-image
#
# Из них принципиальные:
#   * scikit-image — dedoc требует <=0.21.0, а это 2023-пин БЕЗ wheel'ов
#     для Python 3.12 (сборка из исходников падает на meson). Импортируется
#     только PdfImageReader/columns_orientation_classifier — OCR-ридер,
#     который сервис сознательно НЕ подключает. Версию выбирает резолвер.
#   * python-docx / python-multipart — dedoc требует ровно 0.8.11 / 0.0.6,
#     тогда как рабочее окружение держит 1.2.0 / 0.0.9 и всё работает.
#     Для чистой установки приоритет у пина dedoc.
#   * torch / torchvision / transformers — extras dedoc, не тянутся.
#
# xlwt в окружении не установлен: .xls-фикстура генерируется заранее и
# лежит в test_data/sample.xls, поэтому пакет в freeze не попал.

# ОСОЗНАННЫЕ НАРУШЕНИЯ СПЕКОВ dedoc (обязательны для установки)
# ---------------------------------------------------------------------------
# Эти пинны НЕ удовлетворяют тому, что dedoc 2.8 объявляет в метаданных.
# Намеренное отступление от его спеков - иначе установка невозможна.
# Причина: dedoc - пакет 2023 года, его пинны рассчитаны на тогдашний
# стек (starlette 0.27, fastapi 0.104) и несовместимы с современными
# версиями, которые нужны сервису.
#
# Как разрешено: эти пакеты ставятся через `pip install --no-deps dedoc`
# (см. README, раздел «Установка»), а их версии фиксирует ЭТОТ файл.
# Обход безопасен: затрагиваются только необязательные модули dedoc,
# которые сервис не импортирует (см. README, «Отклонения от ТЗ»).
#
#   starlette  dedoc<=0.27.0 | fastapi>=0.37  -> берём fastapi-совместимую
#   fastapi, uvicorn, python-multipart, python-docx, pdfminer.six, ujson,
#   pypdf, pytesseract, puremagic, roman, scipy, scikit-learn,
#   beautifulsoup4, charset-normalizer, xgboost, huggingface-hub,
#   scikit-image  -> версии новee дедук-пинов, без функционального вреда
#
# scikit-image - ОТДЕЛЬНЫЙ СЛУЧАЙ: dedoc требует <=0.21.0, а на Python 3.12
# у этой ветки НЕТ wheels вообще (сборка из исходников падает на meson).
# Импортируется только OCR-ридером PdfImageReader, который сервис
# сознательно не подключает. На Python 3.10/3.11 (версии из ТЗ) pip
# поставит 0.21.0 без проблем.
