Ты — старший Python-разработчик. Твоя задача — с нуля создать (или финализировать) модульный монолитный бэкенд-сервис rag_parser для парсинга структурированных документов, построения их дерева и гибридного чанкинга. 3. Ключевая логика компонентов (КРИТИЧНО)
3.1. Грабли API dedoc==2.8 (Обязательно учесть в dedoc_tree.py)
Текст строки: line.line, НЕ line.text. Может быть вложенным LineWithMeta — раскрывать рекурсивно.
Тип и уровень: line.metadata.data["paragraph_type"] и line.metadata.data["hierarchy_level"] (объект с полями level_1, level_2, line_type). Атрибутов line.type / line.level не существует.
Заголовки в dedoc называются "header", не "heading".
Ячейка таблицы: CellWithMeta, у неё нет атрибута .text. Текст доставать через cell.get_text() или обход cell.lines → ln.line. Запрещено использовать str(cell).
3.2. Breadcrumb и Вложенность (ПРАВИЛО 2-Х УРОВНЕЙ)
Путь заголовков от корня до родителя чанка, разделитель " > ".
Жёсткое ограничение глубины: максимум 2 последних уровня вложенности.
Если структура 1.1 → 1.1.1, берем оба: "[1.1 Название > 1.1.1 Название] текст".
Если структура 1.1 → 1.1.1 → 1.1.1.1, берем только два последних: "[1.1.1 Название > 1.1.1.1 Название] текст".
Если над чанком нет ни одного заголовка, breadcrumb = None.
3.3. Обработка таблиц (СТРОГИЕ ПРАВИЛА)
Позиционная целостность: Таблицы не должны "укатываться" в конец документа. Они остаются в том узле дерева, где были в оригинале.
Заголовок таблицы: У таблицы должен быть реальный заголовок (ближайший preceding header или caption). К этому заголовку также применяется правило "максимум 2 последних уровня" для breadcrumb.
Размер чанка таблицы: ЖЁСТКОЕ требование. Все таблицы обрабатываются строго по 1 строке данных за раз (без параметров выбора количества строк). Каждый чанк таблицы содержит: заголовок таблицы + 1 строку данных.
Dual representation: text = Markdown (с |), text_for_embedding = естественный язык ("Заголовок1: значение1, ...") без символов |, с префиксом [breadcrumb].
3.4. Child-Parent логика для Retrieval (НОВОЕ)
Каждому чанку присваивается parent_id (уникальный ID ближайшего/последнего заголовка, к которому относится чанк).
Каждому чанку присваивается chunk_order (порядковый номер внутри этого родителя).
Логика поиска:
Если у найденного чанка ЕСТЬ parent_id, система возвращает ВСЕ чанки с этим parent_id, отсортированные по возрастанию chunk_order.
Если у найденного чанка НЕТ parent_id (в документе не было заголовков), система возвращает ТОЛЬКО этот единственный найденный чанк.
3.5. HeaderPromoter и MergedCells
HeaderPromoter: Скоринг узлов дерева ДО генерации Markdown. Баллы: Regex нумерации (+3), bold=True (+2), size > 14 (+1.5), КАПС (+1), длина < 100 (+1), alignment=center (+0.5), предложение с точкой и >120 симв (-2). Порог HEADER_PROMOTION_THRESHOLD (дефолт 4.0).
MergedCells: Forward-fill для таблиц xlsx/xls. Значение из левой/верхней ячейки диапазона копируется вправо и вниз внутри объединенного диапазона.
3.6. Скрипт пакетной обработки (scripts/process_input_folder.py)
Сканирует папку input/ и находит все файлы с поддерживаемыми расширениями.
Для каждого файла запускает полный пайплайн: DedocParser -> HybridRagChunker.
Сохраняет результаты в папку output/ с понятными именами:
output/{имя_файла}_parsed.md (итоговый Markdown)
output/{имя_файла}_chunks.json (чанки с breadcrumb, parent_id, chunk_order)
output/{имя_файла}_tree.json (структурное дерево)
Использует tqdm для прогресс-бара. При ошибке парсинга одного файла логирует её и переходит к следующему.
