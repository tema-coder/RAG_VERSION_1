# ЭТАП 3: Таблицы строго по 1 строке + удаление table_chunk_size (ГОТОВ К ВЫПОЛНЕНИЮ)

Этап 2 принят полностью. Breadcrumb = 2 уровня работает корректно на синтетике и в бою.
Теперь переходим к жёсткому ограничению табличного чанкинга.

## Задача
Принудительно разбивать таблицы по 1 строке данных + заголовок. Удалить параметр table_chunk_size из всей системы.

## Что сделать
1. chunkers/table.py:
   - Удалить параметр chunk_size из __init__ TableChunkerRAG.
   - В _fallback_chunks() жёстко задать размер группы = 1.
   - Если используется chonkie.TableChunker(tokenizer="row"), убедиться, что он тоже даёт ровно 1 строку. 
     Если chonkie позволяет менять размер — форсировать chunk_size=1 или заменить на fallback.
   - Инвариант: каждый чанк содержит header + separator + ровно 1 data row.

2. chunkers/hybrid.py:
   - Удалить table_chunk_size из __init__ HybridRagChunker.
   - При создании TableChunkerRAG не передавать table_chunk_size.

3. api/schemas.py:
   - Удалить поле table_chunk_size из ParseRequest / ChunkingParams.

4. api/dependencies.py:
   - Удалить валидацию и резолвинг table_chunk_size.

5. api/routes.py:
   - Удалить table_chunk_size из параметров эндпоинта POST /api/parse.
   - Удалить передачу table_chunk_size в get_chunker().

6. frontend/app.py:
   - Удалить слайдер/поле ввода "Table chunk size" из UI.
   - Убрать table_chunk_size из вызова API.

7. core/config.py:
   - Удалить DEFAULT_TABLE_CHUNK_SIZE (если есть).

8. Тесты:
   - Обновить test_table_chunker: проверить, что для таблицы с N строками данных создаётся ровно N чанков.
   - Добавить инвариантный тест: text_for_embedding не содержит "|", text содержит "|".
   - Проверить, что breadcrumb присутствует в обоих представлениях табличного чанка.
   - Убедиться, что старые тесты, использующие table_chunk_size, обновлены или удалены.

## Критерии приёмки Этапа 3
- pytest rag_parser/tests/test_chunkers.py::test_table_chunker -q → зелёный.
- Для таблицы с 5 строками данных → ровно 5 чанков.
- Ни один чанк таблицы не содержит более 1 строки данных.
- table_chunk_size отсутствует во всех схемах, роутах, зависимостях и UI.
- Покрытие chunkers/ ≥ 90% (было 92%, запас есть).
- Никаких других изменений в коде. Только таблицы и удаление параметра.

Выполни Этап 3. После завершения сообщи:
1. Результат прогона тестов чанкеров.
2. Количество чанков для тестовой таблицы с известным числом строк (подтверждение "ровно 1").
3. Отсутствие table_chunk_size в grep -rn "table_chunk_size" rag_parser/.

Не коммить промежуточные изменения. Жди подтверждения перед Этапом 4 (parent_id + chunk_order).
