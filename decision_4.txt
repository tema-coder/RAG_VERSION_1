# ЭТАП 4: parent_id + chunk_order (ГОТОВ К ВЫПОЛНЕНИЮ)

Этап 3 принят полностью. Таблицы строго по 1 строке работают корректно. 
Теперь внедряем метаданные для группировки чанков при поиске.

## Задача
Добавить поля parent_id и chunk_order в Chunk, реализовать их заполнение в HybridRagChunker и вывести в API.

## Что сделать
1. core/interfaces.py:
   - В dataclass Chunk добавить:
     parent_id: Optional[str] = None
     chunk_order: int = 0
   - Обновить to_dict(), чтобы эти поля попадали в сериализацию.

2. api/schemas.py:
   - В ChunkResponse (Pydantic) добавить parent_id: Optional[str], chunk_order: int.

3. chunkers/hybrid.py:
   - В _chunk_with_tree():
     * Создать стек заголовков (header_stack) и счётчик внутри каждого родителя (order_counter).
     * При обходе узлов дерева: если узел type=="header", добавить его ID в стек, сбросить order_counter для этого уровня.
     * Для каждого текстового/табличного чанка:
       - parent_id = ID верхнего элемента в header_stack (или None, если стек пуст).
       - chunk_order = текущее значение order_counter для этого родителя; после присвоения инкрементировать.
     * ID заголовка должен быть детерминированным: используйте префикс "h_" + порядковый номер заголовка при обходе (p1, p2...). НЕ используйте uuid или хеши текста.
   
   - В _chunk_markdown() (fallback):
     * Реализовать аналогичную логику через парсинг #-заголовков в Markdown.
     * Стек заголовков и order_counter ведутся так же, как в tree-пути.

4. Тесты:
   - test_parent_id_assignment: проверить, что чанки под одним заголовком имеют одинаковый parent_id.
   - test_chunk_order_sequence: проверить, что chunk_order возрастает 0,1,2... внутри одного родителя.
   - test_no_parent_for_orphan_chunks: чанки без заголовков выше имеют parent_id=None.
   - test_table_chunks_have_parent_id: табличные чанки тоже получают parent_id ближайшего заголовка.
   - Проверить, что parent_id стабилен при повторном парсинге того же документа.

## Критерии приёмки Этапа 4
- pytest rag_parser/tests/test_chunkers.py::test_parent* -q → зелёный.
- На реальном документе gost_report.docx: все чанки раздела "2.2" имеют одинаковый parent_id, chunk_order идёт 0,1,2...
- Табличные чанки имеют тот же parent_id, что и соседние текстовые чанки в том же разделе.
- Чанки без заголовков (например, вступление перед первым H1) имеют parent_id=None.
- API возвращает parent_id и chunk_order в ответе POST /api/parse.
- Никаких других изменений в коде. Только метаданные чанков.

3. Отсутствие регрессий в существующих тестах (293 passed должно сохраниться).
