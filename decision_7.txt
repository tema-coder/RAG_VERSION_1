# ЭТАП 7: scripts/process_input_folder.py (ГОТОВ К ВЫПОЛНЕНИЮ)

Этап 6 принят полностью. Обработка PDF-сканов → 422 работает корректно.
Теперь реализуем скрипт автоматической обработки папки input/.

## Задача
Создать скрипт, который сканирует input/, парсит все поддерживаемые файлы и сохраняет результаты в output/.

## Что сделать
1. scripts/process_input_folder.py (НОВЫЙ файл):
   - Импортировать DedocParser, HybridRagChunker, settings из core/config.
   - Получить список файлов в input/ с расширениями из SUPPORTED_EXTENSIONS.
   - Для каждого файла:
     * Логировать начало обработки: "Processing {filename}..."
     * Вызвать parser.parse(file_path) → ParseResult.
     * Если chunking_type не None → вызвать chunker.chunk(result.markdown, tree=result.tree).
     * Сохранить в output/:
       - {stem}_parsed.md (result.markdown)
       - {stem}_chunks.json (json.dumps([c.to_dict() for c in result.chunks], indent=2))
       - {stem}_tree.json (json.dumps(result.tree.to_dict(), indent=2))
     * При ошибке: логировать через structlog.error("parse_failed", filename=..., error=str(exc)), продолжить цикл.
   - Использовать tqdm для прогресс-бара.
   - В конце вывести сводку: "Processed X/Y files successfully".

2. Тесты (tests/test_process_input_folder.py):
   - test_script_processes_valid_files: создать временную папку input/ с 2 файлами (.docx, .txt), запустить скрипт, проверить наличие 6 файлов в output/.
   - test_script_handles_broken_file: добавить битый файл в input/, проверить что скрипт не падает, а логирует ошибку; остальные файлы обрабатываются.
   - test_script_skips_unsupported_extensions: добавить .exe в input/, проверить что он игнорируется.
   - Все тесты использовать tmp_path, не трогать реальную папку input/.

3. README (черновик раздела):
   - Добавить секцию "Пакетная обработка": описание скрипта, пример команды `python -m rag_parser.scripts.process_input_folder`.
   - Указать, что скрипт использует те же настройки, что и API (chunk_size, overlap и т.д. из config.py).
